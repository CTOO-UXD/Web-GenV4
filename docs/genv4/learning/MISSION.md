# Mission: 独立维护 GenV4 组件库

## Why
作为第一次参与组件库开发的工程师，能够把 Figma 和产品需求准确落到 GenV4 的正确层级，避免误改 Google 生成文件或把全局设计变化散落到单个组件中。

## Success looks like
- 能从一个组件标签追踪到 Lit 类、模板、样式、Token 和构建产物
- 能判断需求应修改 System Token、Component Token、内部 SCSS、组件逻辑、文档还是 Demo
- 能完成一次组件修改，并用构建、测试和独立验收页证明结果
- 能识别生成文件和稳定扩展入口，保持后续同步上游的能力

## Constraints
- 主要在 Windows 和 Cursor Agent 中开发
- 需要尽量保持与 Google Material Web 上游结构一致
- 使用中文、具体代码和当前仓库实例学习
- 每节课短小、可复习，并包含即时反馈练习

## Out of scope
- 重建 Google 内部 Design Token 生成器
- 一次性掌握全部组件和全部 Material 规范
- 当前阶段覆盖移动端原生设计系统或多平台 Token 生成
