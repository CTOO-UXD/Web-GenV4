一颗 Button 如何成为像素

今天只建立一个能力：看到 Button 需求后，能沿着真实代码链找到正确修改层，而不是凭文件名猜。

完成标志

你能不看答案说清楚： <md-filled-button> 如何经过 TypeScript、Lit、Token、SCSS 和构建，最终让浏览器画出背景色。

先拿住全景：两条链汇合

Button 不是一条从上到下的文件链，而是“结构行为”和“视觉样式”两条链在公开组件类汇合。

System Token

先记住一句话：TypeScript 决定“里面有什么、怎么交互”；Token + SCSS 决定“长什么样”。

第 1 站：HTML 先触发元素注册

消费者写的是：

<script type="module" src="/button/filled-button.js"></script>

<md-filled-button>保存</md-filled-button>

浏览器本来不认识这个标签。入口文件 button/filled-button.ts 用 Lit 的装饰器完成注册： 

@customElement('md-filled-button')
export class MdFilledButton extends FilledButton {
  static override styles = [
    sharedStyles,
    sharedElevationStyles,
    filledStyles,
  ];
}
这一层只负责两件关键事
  1. 把标签名 md-filled-button 绑定到类。
  2. 把共享样式、elevation 样式和 filled 专属样式组装进 Lit 的 static styles。

HTMLElementTagNameMap 只为 TypeScript 提供类型推断，不负责运行时注册。 可对照 Lit 官方的 Defining a component。

第 2 站：继承把“共性”和“变体”拆开

internal/filled-button.ts 很短，因为 Filled 变体只增加 elevation： 

export class FilledButton extends Button {
  protected override renderElevationOrOutline() {
    return html`<md-elevation part="elevation"></md-elevation>`;
  }
}

真正的共享实现位于 internal/button.ts： 

protected override render() {
  const isRippleDisabled = this.disabled || this.softDisabled;
  const buttonOrLink = this.href ? this.renderLink() : this.renderButton();

  return html`
    ${this.renderElevationOrOutline?.()}
    <div class="background"></div>
    <md-focus-ring ...></md-focus-ring>
    <md-ripple ... ?disabled="${isRippleDisabled}"></md-ripple>
    ${buttonOrLink}
  `;
}

所以同一个自定义元素内部实际包含背景、focus ring、ripple，以及原生 button 或 a。

为什么还要保留原生 button / a？

自定义元素负责组件 API；原生元素继续提供键盘、链接和表单等平台语义。外层是 Shadow Host，模板渲染在 Shadow DOM 中。 这正是 Shadow DOM 用来封装内部结构和样式的场景。

第 3 站：属性变化如何进入模板

以 soft-disabled 为例：

@property({
  type: Boolean,
  attribute: 'soft-disabled',
  reflect: true,
})
softDisabled = false;
  • @property：告诉 Lit 这是响应式公共属性。
  • attribute: 'soft-disabled'：HTML 使用 kebab-case 名字。
  • type: Boolean：负责 attribute 与 property 的布尔转换。
  • reflect: true：property 改变时也反映回 attribute，供 CSS 选择器使用。

它同时影响行为和样式：

// TypeScript：阻止事件和默认行为
if (this.softDisabled || (this.disabled && this.href)) {
  event.stopImmediatePropagation();
  event.preventDefault();
}

// SCSS：改变鼠标与视觉状态
:host(:is([disabled], [soft-disabled])) {
  cursor: default;
  pointer-events: none;
}

第 4 站：背景色从 System Token 走到 Component Token

上游生成文件 tokens/versions/v0_192/_md-comp-filled-button.scss 给出 Material 设计映射： 

@function values($deps: $_default, ...) {
  @return (
    'container-color':
      map.get($deps, 'md-sys-color', 'primary'),
    'label-text-color':
      map.get($deps, 'md-sys-color', 'on-primary'),
    'container-shape':
      map.get($deps, 'md-sys-shape', 'corner-full'),
    ...
  );
}

这不是最终 CSS，而是一张 Sass Map：Filled Button 的 container-color 默认引用系统语义 primary。

为什么有 versions 和不带 versions 的两个文件？

versions/v0_192 是带版本的生成快照，文件头明确写着不要手改； tokens/_md-comp-filled-button.scss 是稳定公共适配层，负责校验、重命名、补充逻辑形状与 CSS 变量回退。上游升级时，稳定层可以吸收生成模型的差异。

第 5 站：公开变量转成内部变量，再落到节点

公共 Token 文件为每项加入可覆盖的回退： 

// tokens/_md-comp-filled-button.scss
$tokens: map.set(
  $tokens,
  $token,
  var(--md-filled-button-#{$token}, #{$value})
);

Filled Button 的 SCSS 再把这张 Map 输出为 Shadow DOM 内使用的私有变量： 

// button/internal/_filled-button.scss
@mixin styles() {
  $tokens: tokens.md-comp-filled-button-values();

  :host {
    @each $token, $value in $tokens {
      --_#{$token}: #{$value};
    }
  }
}

最终，共享样式消费私有变量：

// button/internal/_shared.scss
.background {
  background: var(--_container-color);
}

.button {
  color: var(--_label-text-color);
}
现在把完整颜色链读出来

md-sys-color.primary → --md-filled-button-container-color → --_container-color → .background { background: ... }

公开变量允许消费者主题化，私有变量让内部 SCSS 统一消费。Material Web 官方 Theming 文档 将这三层定义为 System role、Component token 和具体组件实现。

第 6 站：SCSS 如何变成 Lit 能导入的代码

浏览器不会执行 SCSS，TypeScript 也不能直接 import SCSS。构建链做了两次转换：

button/internal/filled-styles.scss
  │ npm run build:sass
  ▼
button/internal/filled-styles.css
  │ npm run build:css-to-ts
  ▼
button/internal/filled-styles.cssresult.ts
  │ npm run build:ts
  ▼
button/filled-button.js

最开始看到的 filledStyles，正是从生成的 cssresult.ts 导入。 Lit 将它放进组件 Shadow Root。可对照官方 Styles 文档中的 static styles。

源码与产物的边界

通常修改 .ts、公共 tokens/*.scss 或 internal/_*.scss；不要直接修改 .css、.cssresult.ts、 .js 和 tokens/versions/**。

三个真实需求，分别怎么改

例 1：只把一颗 Filled Button 改成错误色

md-filled-button.danger {
  --md-filled-button-container-color: var(--md-sys-color-error);
  --md-filled-button-label-text-color: var(--md-sys-color-on-error);
}

这是消费端实例主题，不应改变库默认值。

例 2：GenV4 所有 Filled Button 默认改成品牌绿色

// 示意：放在 GenV4 的稳定覆盖层，而不是 versions 生成目录
$filled-button-overrides: (
  'container-color': #315c49,
);

这是 Component Token 级需求。若设计说的是“全系统 primary 改成绿色”，才应该改 System Token； 两句话的影响范围完全不同。

例 3：soft-disabled 仍触发点击监听

这是行为缺陷，入口在 button/internal/button.ts 的 handleClick()， 验证入口是 button/filled-button_test.ts 或共享 Button 测试，而不是 Token 文件。

本课的最小复述

  1. button/filled-button.ts 注册元素并组装样式。
  2. internal/button.ts 提供共享 Shadow DOM、属性和行为。
  3. 版本 Token 把组件属性映射到 System Token；稳定 Token 层添加公开 CSS 变量回退。
  4. 组件 SCSS 把公开值转为 --_*，再应用到内部节点。
  5. 构建把 SCSS 变成 CSSResult，再由 Lit 安装进 Shadow Root。
