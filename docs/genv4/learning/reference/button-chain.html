需求 → 修改层

整个设计系统的 primary 都改变

System Token：从 tokens/_md-sys-color.scss 的稳定入口处理。

仅 Filled Button 默认背景改变

Component Token：覆盖 --md-filled-button-container-color，或在稳定组件 Token 入口调整映射。

背景色已经正确，但没有应用到背景节点

组件内部 SCSS：检查 button/internal/_shared.scss 中 .background 对 --_container-color 的消费。

disabled 点击仍然触发业务监听器

组件逻辑：检查 button/internal/button.ts 的 handleClick()，并在 filled-button_test.ts 或共享测试中补行为测试。

只想让某个页面的一颗按钮变红

消费端 CSS：给该实例设置 --md-filled-button-container-color，不要修改库默认值。

Playground 展示文案或组合不对

Demo：修改 button/demo/stories.ts；这不改变组件实现。

三个颜色名字，不是同一层

// System role：跨组件的语义
--md-sys-color-primary

// Component token：Filled Button 的公开主题 API
--md-filled-button-container-color

// Private token：Shadow DOM 内部实现细节
--_container-color

默认链路通常是： primary → filled-button-container-color → _container-color → .background。

禁止直接修改

  • tokens/versions/**：文件头写有 “AUTOMATICALLY GENERATED”。
  • *.css、*.cssresult.ts、*.js：属于构建产物，会被下次构建覆盖。

修改后的最短验证

  1. 运行对应构建，确认 SCSS → CSS → cssresult.ts → JS 成功。
  2. 运行相关 Button 单测，验证行为和 Token 输出。
  3. 在独立验收页放 normal、hover、focus、pressed、disabled 和 icon 六种状态。
  4. 确认需求影响范围：单实例、单变体，还是所有使用该 System role 的组件。
